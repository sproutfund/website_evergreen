## Overview

This is the **reverse process** of the export system documented in [MARKDOWN_EXPORT.md](MARKDOWN_EXPORT.md). While the export converts YAML frontmatter to Markdown for portability, the import converts Markdown back to YAML frontmatter for use in the Jekyll website.

**Key Principles:**

1. **Markdown → YAML frontmatter**: Content moves from prose sections to structured YAML
2. **URL normalization**: Full URLs are converted to relative paths
3. **Video URL transformation**: YouTube watch URLs convert to embed URLs
4. **Array creation**: Prose paragraphs become YAML arrays
5. **Nested structures**: Markdown headings map to nested YAML objects

**Source Files:**
- Markdown files in `_content-import/` directory
- External Markdown files from collaborators or AI-generated content

**Destination:**
- YAML frontmatter in `program/*.md` files

---

## Import Process

### Step-by-Step Workflow

1. **Read the source Markdown file** (e.g., `_content-import/remake-learning.md`)
2. **Parse sections by Markdown headings** (##, ###, ####, etc.)
3. **Map each section to its YAML frontmatter equivalent** using the field mapping reference
4. **Transform values** according to conversion rules (URLs, lists, nested structures)
5. **Write the complete YAML frontmatter** to the destination file (`program/remake-learning.md`)
6. **Validate** the output against the frontmatter guide

### File Structure

```
_content-import/
├── remake-learning.md          # Source: Markdown format
└── other-program.md

program/
├── remake-learning.md          # Destination: YAML frontmatter
└── other-program.md
```

## Conversion Rules

### 1. Metadata Section

**Markdown Input:**
```markdown
## Metadata

- **Subtitle:** Strategic stewardship...
- **Description:** From 2012 to 2017...
- **Program:** Remake Learning
- **Superprogram:** Learning
- **Years:** 2012, 2013, 2014, 2015, 2016, 2017
- **Logo:** https://www.sproutfund.org/logos/remake-learning.png
- **URL:** https://www.sproutfund.org/program/remake-learning/
```

**YAML Output:**
```yaml
title: "Remake Learning"                    # From top-level heading (#)
subtitle: "Strategic stewardship..."
description: "From 2012 to 2017..."
program: "Remake Learning"
superprogram: "Learning"
years:
  - 2012
  - 2013
  - 2014
  - 2015
  - 2016
  - 2017
earliest_year: 2012                         # Inferred: first year from years list
logo: "/logos/remake-learning.png"          # Converted from full URL
```

**Rules:**
- Title comes from the top-level `#` heading, not from Metadata section
- `earliest_year` is inferred from the `years` field (see Inferring Earliest Year section below)
- Years: Convert comma-separated string to YAML array
- Logo/URLs: Strip domain prefix, keep only path starting with `/`
- Ignore the **URL:** field (auto-generated by Jekyll)

### 2. Cover Image Section

**Markdown Input:**
```markdown
### Cover Image

- **Source:** https://www.sproutfund.org/photos/programs/remake-learning/network-primer-2013.jpg
- **Caption:** More than 500 educators...
- **Subcaption:** Carnegie Mellon University, February 2013
- **Credit:** photo: The Sprout Fund
```

**YAML Output:**
```yaml
cover-image:
  source: "/photos/programs/remake-learning/network-primer-2013.jpg"
  caption: "More than 500 educators..."
  subcaption: "Carnegie Mellon University, February 2013"
  credit: "photo: The Sprout Fund"
```

**Rules:**
- Create nested object with hyphens in key name (`cover-image`)
- Strip domain from source URL
- All fields are strings (use quotes for safety)
- Omit fields that are empty or not present

### 3. Video Section

**Markdown Input:**
```markdown
### Video

- **URL:** https://www.youtube.com/watch?v=J_g7n2y-t1s?rel=0
- **Title:** What is Remake Learning?
- **Caption:** An overview of the Remake Learning Network...
- **Duration:** 3 minutes
- **Thumbnail:** https://www.sproutfund.org/photos/video_thumbnails/remake-learning.jpg
```

**YAML Output:**
```yaml
video:
  url: "https://www.youtube-nocookie.com/embed/J_g7n2y-t1s?rel=0&controls=1&showinfo=0&autoplay=1"
  thumbnail: "/photos/video_thumbnails/remake-learning.jpg"
  title: "What is Remake Learning?"
  caption: "An overview of the Remake Learning Network..."
  duration: "3 minutes"
```

**Rules:**
- **Video URL transformation** (critical):
  - Input: `https://www.youtube.com/watch?v=VIDEO_ID` or similar
  - Output: `https://www.youtube-nocookie.com/embed/VIDEO_ID?rel=0&controls=1&showinfo=0&autoplay=1`
  - Extract VIDEO_ID and rebuild as embed URL
- Strip domain from thumbnail URL
- Optional fields: `date` (if present in source)

### 4. Context Section

**Markdown Input:**
```markdown
## Context

**Connecting a region to create the future of learning.**

What began in 2007 as a series of informal breakfast meetings...

By late 2011, after early catalytic projects...

Sprout's stewardship was built on a "learning innovation ecosystem" model...
```

**YAML Output:**
```yaml
context:
  heading: "Connecting a region to create the future of learning."
  details:
    - "What began in 2007 as a series of informal breakfast meetings..."
    - "By late 2011, after early catalytic projects..."
    - "Sprout's stewardship was built on a \"learning innovation ecosystem\" model..."
```

**Rules:**
- First paragraph (bold or emphasized) → `heading`
- Remaining paragraphs → `details` array
- Each paragraph becomes one array item (preserve as single string)
- Escape internal quotes with backslash
- Preserve HTML tags like `<em>` if present

### 5. By the Numbers Section

**Markdown Input:**
```markdown
## By the Numbers

- **Years Active (Sprout Stewardship):** 2012–2017
- **Total Sprout Catalytic Investment:** $3.1 million
- **Total Network-Wide Investment:** $72 million (from all funders, by 2017)
- **Network Growth:** From ~60 individuals (2011) to 533 organizations (2017)
```

**YAML Output:**
```yaml
by-the-numbers:
  - heading: "Years Active (Sprout Stewardship)"
    data: "2012–2017"
  - heading: "Total Sprout Catalytic Investment"
    data: "$3.1 million"
  - heading: "Total Network-Wide Investment"
    data: "$72 million (from all funders, by 2017)"
  - heading: "Network Growth"
    data: "From ~60 individuals (2011) to 533 organizations (2017)"
```

**Rules:**
- Each bullet becomes an object with `heading` and `data`
- Preserve full text in `data` (including parentheticals)
- If a link is present: `([link](URL))` → add `link: "URL"` to the object
- Use `local://` prefix for internal links (e.g., `local://downloads/report.pdf`)

### 6. Highlights Section

This is the most complex conversion, as it involves nested structures and multiple feature types.

#### Basic Highlight with Description

**Markdown Input:**
```markdown
## Highlights

### Network Support Strategies (The "Plays")

Sprout's stewardship was organized around five core strategies...

#### Convene: A Community of Practice

We brought people together face-to-face...

- **Kids+Creativity Network Primer (2013):** A landmark event...
- **Annual Network Assembly:** A yearly capstone event...
```

**YAML Output:**
```yaml
highlights:
  - title: "Network Support Strategies (The \"Plays\")"
    description:
      - "Sprout's stewardship was organized around five core strategies..."
    sections:
      - title: "Convene: A Community of Practice"
        description:
          - "We brought people together face-to-face..."
        features:
          - title: "Kids+Creativity Network Primer (2013)"
            description: "A landmark event..."
          - title: "Annual Network Assembly"
            description: "A yearly capstone event..."
```

**Rules:**
- `###` heading → top-level highlight `title`
- Paragraphs after `###` → highlight `description` array
- `####` heading → section `title` within highlight
- Paragraphs after `####` → section `description` array
- Bullet list items → `features` array

#### Features with Images and Links

**Markdown Input:**
```markdown
- **Project Name**: Description text *GRANT-123* [image](/photos/programs/photo.jpg)
- **Manual Feature**: Description text [image](/photos/photo.jpg) [link](https://external.com)
```

**YAML Output:**
```yaml
features:
  - title: "Project Name"
    grant-id: "GRANT-123"                    # Extract from italic text
    # Other fields auto-populated from grants.csv

  - title: "Manual Feature"
    image: "/photos/photo.jpg"
    description: "Description text"
    link: "https://external.com"
```

**Rules:**
- Italic text in format `*GRANT-ID*` → `grant-id` field (rest auto-populated from CSV)
- `[image](URL)` → `image` field (strip domain if full URL)
- `[link](URL)` → `link` field
- For local links, use `local://` prefix
- Description is the text between `**Title**:` and any metadata tags

### 7. Acknowledgements Section

**Markdown Input:**
```markdown
## Acknowledgements

### Supporters

- The Grable Foundation
- John D. and Catherine T. MacArthur Foundation

### Partners

- Remake Learning Council
- Carnegie Mellon University (CREATE Lab, Entertainment Technology Center)

### Staff

- Cathy Lewis Long
- Matt Hannigan
```

**YAML Output:**
```yaml
acknowledgements:
  - title: "Supporters"
    items:
      - "The Grable Foundation"
      - "John D. and Catherine T. MacArthur Foundation"
  - title: "Partners"
    items:
      - "Remake Learning Council"
      - "Carnegie Mellon University (CREATE Lab, Entertainment Technology Center)"
  - title: "Staff"
    items:
      - "Cathy Lewis Long"
      - "Matt Hannigan"
```

**Rules:**
- Each `###` heading → new acknowledgement group
- Bullet items → `items` array
- Preserve parentheticals and special formatting
- For name/title format, use pipe separator: `"Name|Title"` (not shown in this example)

## Field Mapping Reference

| Markdown Section | YAML Field | Notes |
|------------------|------------|-------|
| `# Title` | `title` | Top-level heading |
| `## Metadata` → **Subtitle** | `subtitle` | Direct mapping |
| `## Metadata` → **Description** | `description` | Direct mapping |
| `## Metadata` → **Program** | `program` | Direct mapping |
| `## Metadata` → **Superprogram** | `superprogram` | "Community" or "Learning" |
| `## Metadata` → **Years** | `years` | CSV → YAML array |
| (Inferred from years) | `earliest_year` | First year from `years` field |
| `## Metadata` → **Logo** | `logo` | Strip domain prefix |
| `## Metadata` → **Keywords** | `keywords` | Optional, if present |
| `### Cover Image` → **Source** | `cover-image.source` | Strip domain |
| `### Cover Image` → **Caption** | `cover-image.caption` | Direct |
| `### Cover Image` → **Subcaption** | `cover-image.subcaption` | Optional |
| `### Cover Image` → **Credit** | `cover-image.credit` | Optional |
| `### Video` → **URL** | `video.url` | Transform to embed |
| `### Video` → **Title** | `video.title` | Direct |
| `### Video` → **Caption** | `video.caption` | Direct |
| `### Video` → **Duration** | `video.duration` | Optional |
| `### Video` → **Date** | `video.date` | Optional |
| `### Video` → **Thumbnail** | `video.thumbnail` | Strip domain |
| `## Context` → First bold paragraph | `context.heading` | Extract bold text |
| `## Context` → Remaining paragraphs | `context.details` | Array |
| `## By the Numbers` → Bullet items | `by-the-numbers` | Array of objects |
| `## Highlights` → `###` heading | `highlights[].title` | Top-level highlight |
| `### Highlight` → Paragraphs | `highlights[].description` | Array |
| `#### Section` → Heading | `highlights[].sections[].title` | Subsection |
| `#### Section` → Paragraphs | `highlights[].sections[].description` | Array |
| Bullet items with `*GRANT-ID*` | `features[].grant-id` | Extract grant ID |
| Bullet items (manual) | `features[]` | Manual feature object |
| `## Acknowledgements` → `###` heading | `acknowledgements[].title` | Group name |
| `### Ack` → Bullet items | `acknowledgements[].items` | Array |

## Special Cases and Transformations

### URL Normalization

**Rule:** Strip `https://www.sproutfund.org` prefix from all URLs

```
Input:  https://www.sproutfund.org/photos/programs/remake-learning/photo.jpg
Output: /photos/programs/remake-learning/photo.jpg

Input:  https://external-site.com/resource
Output: https://external-site.com/resource (no change)
```

### Video URL Transformation

**YouTube Watch → Embed:**

```javascript
// Pseudo-code transformation
function convertToEmbed(watchUrl) {
  // Extract video ID from various formats
  let videoId = extractVideoId(watchUrl);
  // https://www.youtube.com/watch?v=VIDEO_ID
  // https://youtu.be/VIDEO_ID
  // etc.

  return `https://www.youtube-nocookie.com/embed/${videoId}?rel=0&controls=1&showinfo=0&autoplay=1`;
}
```

**Examples:**
```
Input:  https://www.youtube.com/watch?v=J_g7n2y-t1s
Output: https://www.youtube-nocookie.com/embed/J_g7n2y-t1s?rel=0&controls=1&showinfo=0&autoplay=1

Input:  https://www.youtube.com/watch?v=J_g7n2y-t1s?rel=0
Output: https://www.youtube-nocookie.com/embed/J_g7n2y-t1s?rel=0&controls=1&showinfo=0&autoplay=1

Input:  https://youtu.be/J_g7n2y-t1s
Output: https://www.youtube-nocookie.com/embed/J_g7n2y-t1s?rel=0&controls=1&showinfo=0&autoplay=1
```

### Grant-ID Detection

Features with grant IDs are identified by italic text in the format `*GRANT-ID*`:

```markdown
- **Project Name**: Description text *PGH250-321* [image](/photos/photo.jpg)
```

Becomes:
```yaml
features:
  - title: "Project Name"
    grant-id: "PGH250-321"
```

**Note:** When `grant-id` is present, other fields (image, description, link) are auto-populated from `_data/grants.csv` and should NOT be included in frontmatter.

### Inferring Earliest Year

The `earliest_year` field must be inferred from the `years` field during import. This field enables chronological sorting in the export system.

**Rule:** `earliest_year` is always the first/earliest year from the `years` field.

**Single Year Programs:**
```markdown
**Markdown Input:**
- **Years:** 2013

**YAML Output:**
years: 2013
earliest_year: 2013
```

**Multi-Year Programs (Comma-Separated):**
```markdown
**Markdown Input:**
- **Years:** 2012, 2013, 2014, 2015, 2016, 2017

**YAML Output:**
years:
  - 2012
  - 2013
  - 2014
  - 2015
  - 2016
  - 2017
earliest_year: 2012  # First year in the list
```

**Multi-Year Programs (Hyphenated Range):**
```markdown
**Markdown Input:**
- **Years:** 2007–2009

**YAML Output:**
years:
  - 2007
  - 2008
  - 2009
earliest_year: 2007  # Start of range
```

**Implementation Logic:**
```javascript
// Pseudo-code for inferring earliest_year
function inferEarliestYear(yearsField) {
  if (typeof yearsField === 'number') {
    // Single year: 2013
    return yearsField;
  } else if (Array.isArray(yearsField)) {
    // Array of years: [2012, 2013, 2014, ...]
    return Math.min(...yearsField);
  } else if (typeof yearsField === 'string') {
    // Parse string formats:
    // "2012, 2013, 2014" or "2007–2009"
    let years = yearsField.split(/[,–-]/).map(y => parseInt(y.trim()));
    return Math.min(...years);
  }
  return null;
}
```

**Special Cases:**
- If programs start in the same year but need specific sort order, use decimal values:
  - `earliest_year: 2014` (first program in 2014)
  - `earliest_year: 2014.1` (second program in 2014)
  - `earliest_year: 2014.2` (third program in 2014)
  - `earliest_year: 2014.3` (fourth program in 2014)

### Nested Sections vs. Direct Features

**With sections (nested):**
```markdown
### Highlight Title

Highlight description

#### Section Title

Section description

- Feature 1
- Feature 2
```

```yaml
highlights:
  - title: "Highlight Title"
    description: ["Highlight description"]
    sections:
      - title: "Section Title"
        description: ["Section description"]
        features:
          - title: "Feature 1"
          - title: "Feature 2"
```

**Without sections (flat):**
```markdown
### Highlight Title

Highlight description

- Feature 1
- Feature 2
```

```yaml
highlights:
  - title: "Highlight Title"
    description: ["Highlight description"]
    features:
      - title: "Feature 1"
      - title: "Feature 2"
```

### Handling Special Markdown Syntax

**Preserve HTML tags:**
```markdown
Description with <em>emphasis</em> and <strong>bold</strong>
```
→ Keep as-is in YAML strings

**Convert markdown to HTML (if needed):**
- `*italic*` or `_italic_` → `<em>italic</em>`
- `**bold**` or `__bold__` → `<strong>bold</strong>`
- Generally preserve markdown as plain text unless HTML is explicitly needed

**Quote escaping:**
```yaml
description: "She said \"hello\" to the group"  # Escape internal quotes
```

### Numbered Lists in Context

When context paragraphs contain numbered lists (e.g., "five key sectors"), convert them to features:

**Markdown Input:**
```markdown
Sprout's stewardship connected five key sectors:

1. Learning Environments (schools, museums, libraries)
2. Innovation Research & Development (university labs)
3. Learning Scholarship & Advocacy
4. Commercial & Entrepreneurial Engagement
5. Strategic Stewardship
```

**YAML Output:**
```yaml
highlights:
  - title: "Five-Sector Ecosystem Model"
    description:
      - "Sprout's stewardship connected five key sectors..."
    features:
      - title: "Learning Environments"
        description: "Schools, museums, libraries..."
      - title: "Innovation Research & Development"
        description: "University labs..."
      # etc.
```

This makes numbered items more prominent and allows adding images later.

### Malformed or Wrapper URLs

Clean up malformed URLs that may appear in source content:

**Google Search Wrappers:**
```markdown
[image](https://www.google.com/search?q=https://www.sproutfund.org/photos/programs/program-name/photo.jpg)
```

Should be cleaned to:
```yaml
image: "/photos/programs/program-name/photo.jpg"
```

**URL with typos or extra protocols:**
- Remove `httpss://` (double s)
- Fix `http://` to `https://` if needed
- Remove any query parameters that aren't intentional

### Omitting Entire Sections

Unlike individual fields, entire sections can be omitted when:

**Video section with placeholders:**
```markdown
### Video
- **URL:** [VIDEO-ID]
- **Title:** [Title]
```

→ Omit the entire `video:` section from YAML (not even empty)

**Sections to omit when empty:**
- `video:` - Only include if you have actual video data
- `by-the-numbers:` - Omit if no statistics available
- `highlights:` sections without features

**Do NOT omit these (use empty/default values):**
- `context:` - Always include, even if brief
- `acknowledgements:` - Include with placeholder items if needed

### Acknowledgements Special Formatting

**Lead/emphasis designations:**

Input:
```markdown
- Claude Worthington Benedum Foundation (Lead)
- Richard King Mellon Foundation (Lead)
```

Output:
```yaml
items:
  - "<strong>Claude Worthington Benedum Foundation</strong>"
  - "<strong>Richard King Mellon Foundation</strong>"
```

Remove "(Lead)" suffix and wrap in `<strong>` tags instead.

**Parenthetical explanations:**

Keep parentheticals that provide context:
```yaml
items:
  - "GTECH (Growth Through Energy + Community Health)"  # Keep
  - "Carnegie Mellon University (CREATE Lab, ETC, HCII)" # Keep
```

**Staff with date ranges:**

Use pipe separator for staff tenure:
```yaml
items:
  - "Jocelyn Horner|2008-2009"
  - "Ryan Coon|Project Manager"
  - "Mac Howison"
```

The pipe creates a secondary line with lighter text in the rendered output.

### Placeholder Content

When content has placeholders that will be filled later:

**Keep placeholders for:**
- Photo credits: `credit: "photo: [Photographer Name]"`
- Acknowledgements: `items: ["NEED TO ADD"]`

**Comment out missing images:**
```yaml
features:
  - title: "Feature Name"
#   image: "/photos/programs/program-name/feature.jpg"  # Add later
    description: "Feature description"
```

This preserves the intended structure while allowing the page to render without broken images.

### Data Discrepancies

When source content has conflicting information, ask the user:

**Common discrepancies:**
- Years in metadata vs. context (e.g., "2008-2012" vs. "2009-2015")
- Superprogram classification (Community vs. Learning)
- Total investment amounts in different sections
- Project counts that don't match feature lists

**Resolution approach:**
1. Note the discrepancy
2. Ask user which value is authoritative
3. Update all instances to match authoritative value
4. Document the decision in your response

## Validation Checklist

After conversion, validate the output:

- [ ] **YAML syntax is valid** - No tabs, consistent indentation (2 spaces)
- [ ] **Required fields present** - `layout: program`, `title`, `subtitle`, `description`
- [ ] **URLs normalized** - No `https://www.sproutfund.org` prefixes on internal paths
- [ ] **Video URL is embed format** - Uses `youtube-nocookie.com/embed/` structure
- [ ] **Years is array** - Not comma-separated string (unless single year)
- [ ] **Earliest year inferred** - `earliest_year` field matches first year from `years`
- [ ] **Frontmatter enclosed** - Starts and ends with `---`
- [ ] **Quotes escaped** - Internal quotes have backslashes
- [ ] **Grant IDs valid** - Check against `_data/grants.csv` if possible
- [ ] **No body content** - Program pages are frontmatter-only (no content after closing `---`)
- [ ] **Arrays properly formatted** - Each item starts with `-` and proper indentation
- [ ] **Nested objects correct** - cover-image, video, context use proper nesting

### Test Build

After importing, test the conversion:

```bash
bundle exec jekyll build --config "_config.yml,_config_dev.yml"
bundle exec jekyll serve --config "_config.yml,_config_dev.yml" --livereload
```

Visit: `http://localhost:4000/website_evergreen/program/program-name/`

## Troubleshooting

### Issue: YAML syntax error on build

**Symptoms:** Jekyll fails to build with YAML parsing error

**Solutions:**
1. Validate YAML: `ruby -ryaml -e "puts YAML.load_file('program/program-name.md')"`
2. Check indentation (must be spaces, not tabs)
3. Check for unescaped quotes
4. Ensure colons have spaces after them: `key: value` not `key:value`

### Issue: Content not displaying on page

**Symptoms:** Page renders but sections are missing

**Solutions:**
1. Verify field names match exactly (hyphens vs underscores: `cover-image` not `cover_image`)
2. Check that arrays are properly formatted with `-` items
3. Ensure nested objects use correct structure
4. Check template expectations in `_includes/page_parts/*.html`

### Issue: Images not loading

**Symptoms:** Broken image links on page

**Solutions:**
1. Verify paths start with `/` (absolute from site root)
2. Check that images exist in repository
3. Ensure `keep_files` in `_config.yml` includes image directories
4. Rebuild Jekyll after adding new images

### Issue: Videos not playing

**Symptoms:** Video section displays but modal doesn't work

**Solutions:**
1. Verify video URL is in embed format (not watch URL)
2. Check that video ID is correctly extracted
3. Test the embed URL directly in browser
4. Ensure thumbnail path is correct

### Issue: Grant-based features not loading

**Symptoms:** Features display title but no description/image

**Solutions:**
1. Verify `grant-id` exactly matches value in `_data/grants.csv`
2. Check CSV has data in required columns: `project-name`, `short-statement`, `photo`
3. Rebuild Jekyll after CSV changes: `bundle exec jekyll clean && bundle exec jekyll build`
4. Check that grant has `show-hide` == `"show"` if filtering is used

## Common Migration Patterns

Based on real-world migrations, here are patterns that frequently appear:

### Related Programs Section

Most program pages include a "Related Programs" section at the end:

```yaml
highlights:
  - title: "Related Programs"
    description:
      - "Brief explanation of how programs are connected."
    features:
      - title: "Program Name"
        image: "/logos/program-name.png"
        link: "local://program/program-name/"
        description: "How this program relates to the current one."
```

**Pattern:** Each related program becomes a feature with logo image and internal link.

### Programmatic Activities as Features

Events, convenings, or activities often appear as bulleted lists but should become features:

```markdown
## Highlights

### Making Sparks Convening

Key activities:
- **Panel Discussions**: National leaders sharing trends
- **Ideation Sessions**: Brainstorming in small groups
```

Becomes:
```yaml
highlights:
  - title: "Making Sparks Convening"
    description:
      - "Key activities included:"
    features:
      - title: "Panel Discussions"
        description: "National leaders sharing trends"
      - title: "Ideation Sessions"
        description: "Brainstorming in small groups"
```

### Grant-Based Features by Year

Programs with multi-year funding often organize features by year using sections:

```yaml
highlights:
  - title: "Funded Project Highlights"
    sections:
      - title: "Spark 2009"
        features:
          - grant-id: "SPARK-020"
          - grant-id: "SPARK-010"
      - title: "Spark 2010"
        features:
          - grant-id: "SPARK-076"
          - grant-id: "SPARK-038"
```

**Pattern:** Year-based subsections under a parent "Funded Project Highlights".

### Ecosystem/Framework Models

Programs describing multi-part models or ecosystems often list them in context but should become features:

```yaml
highlights:
  - title: "Five-Sector Ecosystem Model"
    description:
      - "Overview of the model..."
    features:
      - title: "Sector 1"
        description: "Description..."
      - title: "Sector 2"
        description: "Description..."
```

**Pattern:** Create a dedicated highlights section for the model with each component as a feature.

### Multi-Stage Process Descriptions

Programs with defined stages (like Engage Pittsburgh's funnel) work well as features:

```yaml
highlights:
  - title: "Programmatic Activities"
    description:
      - "Multi-stage process description..."
    features:
      - title: "Stage 1: Discovery"
        image: "/photos/programs/program/stage1.jpg"
        description: "What happened in this stage"
      - title: "Stage 2: Development"
        image: "/photos/programs/program/stage2.jpg"
        description: "What happened in this stage"
```

**Pattern:** Process stages become chronologically ordered features.

### Alternative Bullet Markers

Source Markdown may use `*` instead of `-` for lists. Both work identically in conversion - treat them the same way:

```markdown
* Item one
* Item two
```

→ Same conversion as:

```markdown
- Item one
- Item two
```

### Staff Ordering

When migrating staff lists, preserve user-specified ordering. Common patterns:
- Alphabetical by last name
- Chronological (by start date)
- By role (leads first, then alphabetical)

**Example from migrations:**
```yaml
staff:
  items:
    - "Cathy Lewis Long"
    - "Matt Hannigan"
    - "Mac Howison"
    - "Dustin Stiver"
```

User may reorder after migration based on their preference.

## Summary

The Markdown import process is essentially the reverse of the export:

1. **Parse** Markdown headings and content into structured sections
2. **Transform** URLs, video links, and arrays according to conversion rules
3. **Map** each section to its YAML frontmatter equivalent
4. **Handle special cases** like numbered lists, malformed URLs, and placeholders
5. **Validate** syntax and required fields
6. **Test** with Jekyll build to ensure correct rendering

**Key principles learned from real migrations:**
- Always infer `earliest_year` from the `years` field (first year in list or single year value)
- Convert numbered lists and process descriptions into features for better presentation
- Clean malformed URLs (Google search wrappers, typos)
- Omit entire sections (like video) when data is incomplete
- Use strong tags for lead supporters, pipe separators for staff roles
- Preserve parenthetical explanations that add context
- Comment out image paths when assets aren't ready yet
- Ask about data discrepancies before making assumptions

By following the field mapping reference, conversion rules, and common patterns documented here, you can reliably convert standalone Markdown content back into the YAML frontmatter structure used by program pages.
